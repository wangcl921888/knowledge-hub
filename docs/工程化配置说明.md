# 工程化配置说明（新手必读）

本文档讲解两个「不能写注释的 JSON 文件」：`package.json` 和 `turbo.json`。
因为标准 JSON 格式不支持注释，硬加会让程序报错，所以说明写在这里。

---

## 一、package.json（项目根配置）

项目的"总控台"，记录项目信息、脚本命令、依赖。

| 字段 | 值 | 作用（大白话） |
|---|---|---|
| `name` | knowledge-hub | 项目名字 |
| `version` | 0.0.0 | 版本号，从 0 开始，以后用语义化版本管理 |
| `private` | true | 标记为私有，防止手滑把整个项目发布到 npm 公网 |
| `description` | ... | 项目描述 |
| `packageManager` | pnpm@10.4.1 | 锁定包管理器和版本，保证团队每个人用的 pnpm 完全一致 |
| `engines.node` | >=20 | 要求 Node 版本 ≥ 20，版本太低会有兼容问题 |

### scripts（脚本命令）

这些是"快捷命令"，用 `pnpm 命令名` 运行。它们都调用 turbo 去调度所有子项目：

| 命令 | 运行方式 | 作用 |
|---|---|---|
| `build` | `pnpm build` | 构建所有子项目（打包成能上线的代码） |
| `dev` | `pnpm dev` | 启动所有子项目的开发服务器（本地边写边看效果） |
| `lint` | `pnpm lint` | 检查所有代码的规范问题 |
| `typecheck` | `pnpm typecheck` | 检查所有 TS 类型错误 |
| `test` | `pnpm test` | 跑所有测试 |
| `clean` | `pnpm clean` | 清理构建缓存 |

> 关键点：`turbo run dev` 的意思是"让 Turborepo 去每个子项目里执行它们各自的 dev 命令"。
> 这就是 monorepo 的威力——一条命令管理所有子项目。

### devDependencies（开发依赖）

只在开发时用的工具，不会打包进最终上线的代码：

| 依赖 | 作用 |
|---|---|
| `turbo` | Turborepo，monorepo 的任务调度 + 构建缓存工具 |
| `typescript` | TypeScript 编译器 |

> 小知识：`^2.5.0` 里的 `^` 表示"允许自动升级到 2.x 的最新版本，但不升到 3.0"。

---

## 二、turbo.json（Turborepo 任务编排配置）

定义每个任务怎么跑、跑完缓存什么。核心价值是**提速**：没改动的代码不会重复构建。

| 字段 | 作用（大白话） |
|---|---|
| `$schema` | 让编辑器能自动提示 turbo.json 的字段 |
| `tasks` | 所有任务的定义集合 |

### 各任务详解

**build（构建）**

```jsonc
"dependsOn": ["^build"]
"outputs": [".next/**", "!.next/cache/**", "dist/**"]
```

- `dependsOn: ["^build"]`：`^` 表示"先构建我依赖的其它包"。
  比如 web 应用依赖 packages/ui，就先把 ui 构建好，再构建 web。
- `outputs`：告诉 turbo 构建会产生哪些文件，turbo 把它们缓存起来。
  `!.next/cache/**` 里的 `!` 表示"排除这个，不要缓存"（缓存它反而没用还占空间）。

**dev（开发服务器）**

```jsonc
"cache": false
"persistent": true
```

- `cache: false`：开发模式不需要缓存，每次都要最新的。
- `persistent: true`：这是个"常驻不退出"的任务（服务器一直开着），turbo 特殊对待它。

**lint / typecheck（检查）**

- `dependsOn: ["^lint"]`：同理，先检查依赖的包，再检查自己。

**test（测试）**

- `dependsOn: ["^build"]`：跑测试前要先把代码构建好。

**clean（清理）**

- `cache: false`：清理操作不缓存。

> 面试常问：「Turborepo 相比直接跑脚本有什么好处？」
> 答：① 任务依赖编排（自动按正确顺序执行）② 增量构建缓存（没改的不重复跑，大幅提速）。
